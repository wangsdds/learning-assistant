## 一、要支持的动作（MVP 就这 5 个，多一个都不做）

1. 访客能注册（邮箱 + 密码 + 昵称），能登录，能退出
2. 登录后能给「某一天」建一条计划，计划里能写好几个条目（比如「20:00 复习 B+ 树」）
3. 能上传 / 登记一份资料（一个文件，或一个网址），资料属于上传它的那个人
4. 能针对某个资料或者某天的计划，让系统出几道题
5. 我答完题，答题记录要能存下来、以后能回看（对错、什么时候答的）

## 二、四条硬约束（它们决定了表怎么切）

- 多用户：**每条数据都要能回答「这是谁的」**，否则以后一定串数据
- 一条计划有**多个**条目（一对多）
- 一份资料只属于一个人；**不同用户的同名资料不能互相盖掉**（想清楚唯一约束加在哪几个列上）
- 答题记录要能反查：这道题是什么、属于哪份资料、谁在什么时候答的、对还是错
- 删掉一个用户时，他的计划 / 资料 / 记录应该跟着消失（别留孤儿数据）

## 三、自检：每张表都要能回答这 4 个问题

1. **主键是什么**？（哪一列是这行数据的唯一身份证）
2. **这行数据属于谁**？（用户隔离靠哪一列？这张表本身该不该有 owner 列，还是通过别的表间接算出来？）
3. **它引用谁**？（外键指向哪张表的哪一列）
4. **哪些列不能为空 / 哪些列不能重复**？

## 五、语法速查（想直接写 SQL 就看这里；用不到可以跳过）

```sql
CREATE TABLE plan_items (
    id          INTEGER PRIMARY KEY,          -- 主键：这张表每行的唯一身份证
    plan_id     INTEGER NOT NULL,             -- 外键：指向 plans.id
    title       TEXT    NOT NULL,
    done        INTEGER NOT NULL DEFAULT 0,   -- SQLite 没有 bool，用 0/1
    created_at  TEXT    NOT NULL,
    FOREIGN KEY (plan_id) REFERENCES plans(id) ON DELETE CASCADE
);
```

- **主键**：`INTEGER PRIMARY KEY` 在 SQLite 里自带自增，不用自己编号
- **类型只要三种**：`INTEGER` / `TEXT` / `REAL`。SQLite 的类型是「亲和性」，写 `VARCHAR(50)` 不报错但没意义。时间统一用 `TEXT` 存 ISO 字符串（如 `'2026-10-15T20:30:00'`），换 PostgreSQL 时再改
- **不给 `NOT NULL` 就等于允许空**。允许空的列，将来数据里就会有空洞
- **`UNIQUE`**：不允许重复。想清楚加在哪几列（或哪几列的组合）上
- **外键的两个作用**：告诉数据库这行属于谁；`ON DELETE CASCADE` 让删用户时他的数据跟着删
- **坑**：SQLite 默认**不检查**外键，要 `PRAGMA foreign_keys = ON;` 才生效 —— 所以「写在表定义里」和「真的生效」是两件事

## 六、卡住了怎么办

- 先问自己：「这条数据是**一条**还是**一堆**？」一堆的那个，通常要单独一张表
- 拿不准某张表要不要存在，就问：**没有它，上面 5 个动作哪个做不成？** 做不成的才留
